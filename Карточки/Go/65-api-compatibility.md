# Какие изменения Go-пакета ломают совместимость?

## Вопрос

Что считается breaking change для экспортированного API и как эволюционировать функции, интерфейсы и структуры?

## Краткий ответ

Удаление или изменение экспортированного имени/сигнатуры ломает компиляцию. Добавление метода в интерфейс ломает внешние реализации. Добавление поля в экспортированную структуру может ломать positional literals и сравнимость. Эволюцию планируют через новые symbols, options и major version.

## Развёрнутый ответ мидла

- Публичны экспортированные identifiers и наблюдаемое поведение, ошибки и форматы.
- Новая функция безопаснее изменения старой сигнатуры.
- Маленький consumer-owned interface легче эволюционировать.
- Клиенты должны использовать keyed struct literals; библиотека не всегда может заставить внешнего пользователя так делать.

Документация, error categories и concurrency guarantees являются частью практического контракта, даже если компилятор их не проверяет.

## Развёрнутый ответ сеньора: все тонкости

- Добавление метода concrete type обычно совместимо, но может создать конфликт embedding или неожиданно реализовать interface.
- Изменение nil/empty JSON, порядка, timeout или wrapping errors способно сломать runtime-потребителей.
- Semantic versioning требует нового major module path для v2+.
- Deprecation даёт миграционный путь: старый API остаётся рабочим до объявленного удаления.

### Дополнительное техническое объяснение

Compatibility включает source, binary/toolchain и behavioral contracts. Interface method set, exported struct layout, error identity и serialization schema образуют dependency surface. Breaking evolution выпускают через semver major и module path suffix с документированной миграцией.

## Если забыл / Простыми словами

Публичный API — обещание не только компилятору, но и поведению клиентов. Расширяй добавлением, а не неожиданным изменением.

### Аналогия и объяснение

Если другие команды строят код из ваших деталей, изменение формы детали ломает их сборку. Даже незаметное изменение поведения может сломать работающую систему. Поэтому старую деталь оставляют, добавляют новую и дают время перейти.
