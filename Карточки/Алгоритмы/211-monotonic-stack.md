# Что такое monotonic stack?

## Вопрос

Как монотонный стек находит следующий больший или меньший элемент за O(n) вместо полного перебора?

## Краткий ответ

Monotonic stack хранит индексы элементов в возрастающем или убывающем порядке. При новом элементе из стека удаляются элементы, для которых он стал ближайшим ответом. Каждый индекс добавляется и удаляется не более одного раза, поэтому общая сложность O(n), память O(n).

## Развёрнутый ответ мидла

Для next greater element поддерживают убывающий стек: пока `a[stack.top] < a[i]`, ответ для top равен `i`, затем top удаляют. В стеке остаются индексы без найденного большего справа.

Индексы нужны, чтобы вычислять расстояния и различать одинаковые значения. Условие `<` или `<=` выбирают по задаче: ближайший строго больший и больший-or-equal дают разные результаты.

Применения: daily temperatures, stock span, largest rectangle in histogram, boundaries subarray minimum/maximum.

## Развёрнутый ответ сеньора: все тонкости

Доказательство O(n) амортизированное: внутренний while может выполнить много pop на одной итерации, но один элемент нельзя удалить дважды. Для circular array делают два прохода по индексам modulo n, добавляя в стек только нужный проход.

В largest rectangle добавляют sentinel, чтобы вытолкнуть остаток; ширина зависит от нового top после pop. Duplicate policy критична для уникального подсчёта contributions.

### Дополнительное техническое объяснение

Stack хранит unresolved candidates и invariant monotonicity. Новый observation доминирует suffix candidates и завершает их query. Aggregate push/pop count ≤2n даёт linear amortized complexity.

## Если забыл / Простыми словами

В очереди остаются только люди, которые ещё не встретили более высокого справа. Приходит высокий человек и сразу отвечает всем более низким в конце очереди, после чего сам ждёт следующего.

### Аналогия и объяснение

Хотя один высокий человек может вывести много людей, каждый человек входит и выходит только один раз. Поэтому вложенный цикл здесь не превращает алгоритм в O(n²).
