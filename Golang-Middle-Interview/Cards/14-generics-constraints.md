# Как работают generics и constraints в Go?

Что такое type parameter и constraint, зачем нужен `comparable`, что означает `~T` и когда generics лучше интерфейса?

===

@input

---

## Краткий ответ

Type parameter задаёт семейство типов на этапе компиляции, constraint ограничивает допустимые операции. `any` допускает любой тип, `comparable` — типы, поддерживающие `==`/`!=` и ключи map. `~int` включает типы с underlying type `int`.

---

## Развёрнутый ответ мидла

```go
func Contains[T comparable](s []T, want T) bool {
    for _, v := range s {
        if v == want { return true }
    }
    return false
}

type Number interface {
    ~int | ~int64 | ~float64
}

func Sum[T Number](xs []T) T {
    var total T
    for _, x := range xs { total += x }
    return total
}
```

Операции внутри generic-функции определяются constraint. Если constraint не обещает `<`, использовать его нельзя. `~` позволяет именованным типам с тем же underlying type участвовать в constraint.

Generics подходят для алгоритмов и контейнеров, где логика одинакова для разных типов. Обычный интерфейс подходит для динамического поведения через методы.

---

## Развёрнутый ответ сеньора: все тонкости

Constraint — интерфейс, но интерфейсы с type sets, содержащими type terms, обычно предназначены только для constraints и не используются как обычные runtime-типы. Union `A | B` задаёт набор, а пересечение требований достигается встраиванием элементов constraint.

`comparable` означает допустимость сравнения, но сравнение interface-значений всё ещё может паниковать, если динамическое значение несравнимо; нюансы зависят от конкретного type parameter и допустимого набора типов. Для ключа map constraint обязан гарантировать сравнимость.

Type inference часто выводит аргументы из параметров функции, но не из возвращаемого типа. Иногда type arguments приходится указывать явно. Методы не могут вводить собственный дополнительный список type parameters независимо от параметров receiver-типа.

Generics не заменяют интерфейсы. Если алгоритму нужно поведение `Read`, естественен `io.Reader`; если нужен `Min` для разных упорядоченных типов — generic. Generic API может ухудшить сообщения об ошибках компилятора и увеличить сложность, поэтому абстракцию вводят после появления реального повторения.

Не стоит обещать конкретную стратегию реализации (полная мономорфизация или dictionary passing): это деталь компилятора и может зависеть от типов. Производительность проверяют benchmark, размер бинарника — инструментами сборки.

## Если забыл / Простыми словами

Generics отвечают на вопрос **«один алгоритм для набора статических типов»**, interface — **«разные реализации одного поведения во время выполнения»**. Constraint определяет, что разрешено делать с `T`.

### Аналогия и объяснение

Представь, что это одно из правил языка и стандартной библиотеки: оно задаёт, как программа хранит данные или выполняет действие. Понимание правила помогает не угадывать поведение кода, а заранее предсказывать результат, находить ошибки и выбирать более простой API.
