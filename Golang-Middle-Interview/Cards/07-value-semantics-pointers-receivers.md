# Когда выбирать pointer receiver, а когда value receiver?

## Вопрос

Как в Go передаются аргументы и по каким критериям выбирать `(T)` или `(*T)` у метода?

## Краткий ответ

В Go всё передаётся по значению. Указатель тоже копируется, но обе копии указывают на один объект. Pointer receiver нужен для изменения объекта, предотвращения дорогой копии или поддержания единого method set; value receiver подходит небольшим неизменяемым значениям.

## Развёрнутый ответ мидла

```go
type Counter struct{ n int }
func (c Counter) Value() int { return c.n }
func (c *Counter) Inc()      { c.n++ }
```

Метод с value receiver получает копию `Counter`, поэтому изменение полей копии не меняет исходник. Метод с pointer receiver может изменить исходный объект.

Компилятор разрешает `v.Inc()` для адресуемой переменной `v` и неявно берёт `&v`. Это синтаксическое удобство не означает, что method sets `T` и `*T` одинаковы: методы `(T)` входят в набор методов обоих типов, методы `(*T)` — только `*T`.

Обычно все методы конкретного типа делают с одним видом receiver, чтобы поведение и реализация интерфейсов не удивляли.

## Развёрнутый ответ сеньора: все тонкости

Критерий «структура большая» вторичен по отношению к семантике владения. Типы вроде `time.Time` сознательно используют value semantics: значение можно безопасно копировать. Структуру с `sync.Mutex`, `atomic`-полями или внутренними указателями копировать после первого использования нельзя; `go vet` предупреждает о копировании lock value.

Pointer receiver не гарантирует аллокацию в куче: escape analysis может оставить объект на стеке. И наоборот, value может escape из-за хранения в интерфейсе или замыкании. Выбор receiver не следует делать только ради гипотетической аллокации.

Nil pointer receiver технически можно вызвать, если метод умеет обработать `nil`, но обращение к полям вызовет panic. Такой контракт должен быть осознанным и документированным.

Копия дескриптора среза, map или указателя внутри value receiver всё ещё разделяет underlying data. Поэтому «value receiver не изменяет исходник» неверно для транзитивно изменяемого состояния: он не может заменить поля исходной структуры, но может менять общие объекты, на которые поля ссылаются.

Публичный API должен учитывать method set: если интерфейс реализует только `*T`, значение `T` нельзя присвоить этому интерфейсу. Возврат указателей также передаёт вызывающему возможность мутировать состояние.

## Если забыл: что это, зачем и где нужно

Начни ответ фразой **«в Go всё передаётся по значению»**. Потом объясни, что копия указателя сохраняет доступ к тому же объекту, и выбери receiver по семантике изменения, копируемости типа и интерфейсам.
