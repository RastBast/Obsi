# Как работают type assertion и type switch?

## Вопрос

Как извлечь конкретное значение из интерфейса, чем отличаются формы `x.(T)` и `v, ok := x.(T)`, и когда использовать type switch?

## Краткий ответ

Type assertion проверяет динамический тип интерфейса или реализацию другого интерфейса. Однозначная форма при неуспехе паникует; comma-ok возвращает zero value и `false`. Type switch удобно обрабатывает несколько типов.

## Развёрнутый ответ мидла

```go
var x any = 42
n := x.(int)        // 42; panic, если тип другой
n, ok := x.(int)    // безопасная проверка

switch v := x.(type) {
case int:
    fmt.Println(v + 1) // v имеет тип int
case string:
    fmt.Println(len(v))
case nil:
    fmt.Println("nil interface")
default:
    fmt.Printf("%T\n", v)
}
```

Assertion может быть и к интерфейсу: `r, ok := x.(io.Reader)`. Тогда проверяется, реализует ли динамический тип нужный интерфейс.

Type conversion `T(x)` — другая операция: она преобразует совместимые статические типы и не проверяет динамический тип interface так, как assertion.

## Развёрнутый ответ сеньора: все тонкости

Проверка на конкретный тип часто связывает код с реализацией. Сначала стоит спросить, нельзя ли выразить нужное поведение маленьким интерфейсом. Однако на границах — декодирование, драйверы, AST, обработка разнородных событий — type switch может быть самым ясным решением.

`case T` и `case *T` — разные случаи. Typed nil внутри интерфейса попадёт в `case *T`, а не в `case nil`, потому что сам интерфейс ненулевой. После assertion переменная-указатель может оказаться `nil`, это нужно учитывать.

В type switch case с одним типом переменная имеет этот конкретный тип, а case с несколькими типами — тип исходного выражения interface. Это иногда удивляет при попытке вызвать специфичный метод.

Для ошибок предпочтительнее `errors.As`, а не ручной assertion по цепочке: `As` проходит через обёрнутые ошибки. Для сравнения категорий — `errors.Is`. Прямой `err.(*MyError)` видит только верхний динамический тип и ломается после `fmt.Errorf("...: %w", err)`.

Reflection нужна, когда набор типов неизвестен при компиляции; type switch проще, быстрее для чтения и проверяется компилятором, если набор конечен.

## Если забыл / Простыми словами

Assertion отвечает: **«какой динамический тип лежит в interface?»**. В продакшене почти всегда выбирай comma-ok, если panic не является осознанным утверждением инварианта. Для нескольких вариантов — type switch.

Представь, что это одно из правил языка и стандартной библиотеки: оно задаёт, как программа хранит данные или выполняет действие. Понимание правила помогает не угадывать поведение кода, а заранее предсказывать результат, находить ошибки и выбирать более простой API.
