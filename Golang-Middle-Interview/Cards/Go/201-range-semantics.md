# Какие тонкости есть у range в Go?

## Вопрос

Что копирует `range`, какими являются index/value для разных коллекций и почему изменение переменной цикла не всегда изменяет исходный элемент?

## Краткий ответ

`range` присваивает iteration values переменным цикла. Для slice/array значение элемента копируется, поэтому изменение `v` не меняет `s[i]`; нужно менять `s[i]`. Для map порядок не определён. Для string index — byte offset, value — декодированная rune. Семантика loop variables зависит от версии Go в `go.mod`.

## Развёрнутый ответ мидла

```go
for i, v := range users {
    v.Active = true      // меняется только копия v
    users[i].Active = true // меняется элемент slice
}
```

При range по array выражение массива может быть скопировано целиком; range по указателю на array или slice избегает такой семантической копии данных. Map можно изменять во время обхода только по правилам спецификации: удалённый ещё не достигнутый ключ не появится, добавленный может появиться или нет.

Для channel `range` получает значения до закрытия и опустошения. Для integer range в современных версиях генерируется последовательность, но minimum version проекта должна это поддерживать.

## Развёрнутый ответ сеньора: все тонкости

Начиная с новых языковых версий переменные итераций, объявленные через `:=`, создаются отдельно на итерацию, что исправляет классическую ошибку closure capture. Но переменная, объявленная снаружи и присваиваемая через `=`, остаётся общей. Поведение определяется директивой `go` модуля, а не только установленным toolchain.

Взятие `&v` даёт адрес копии iteration value, не элемента коллекции. Для указателя на элемент используют `&s[i]`, учитывая, что последующий append может заменить backing array.

### Дополнительное техническое объяснение

Range expression вычисляется один раз с исключениями/оптимизациями, определёнными спецификацией. Iteration protocol различается для array, slice, string, map, channel, integer и iterator function. Корректность кода должна опираться на language version и documented iteration guarantees, а не на наблюдаемый порядок.

## Если забыл / Простыми словами

Range часто выдаёт не сам предмет из коробки, а его копию для осмотра. Нарисовать что-то на копии недостаточно — для изменения оригинала нужен индекс. У map коробки выдаются в произвольном порядке, у строки номер показывает позицию байта, а не порядковый номер буквы.

### Аналогия и объяснение

Представь каталог с ксерокопиями карточек. `v` — копия текущей карточки, `i` — её место. Чтобы исправить каталог, нужно открыть оригинал по `i`. Это объясняет большинство ошибок с range, указателями и goroutine.
