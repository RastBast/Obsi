# Чем nil map отличается от пустой map?

## Вопрос

Можно ли читать и писать в `nil` map? Как отличить отсутствующий ключ от нулевого значения и как реализовать множество?

## Краткий ответ

Из `nil` map можно читать, по ней можно делать `range`, вызывать `len` и `delete`; всё ведёт себя как с пустой map. Запись вызывает panic. Наличие ключа проверяют формой `v, ok := m[k]`. Множество обычно делают как `map[T]struct{}`.

## Развёрнутый ответ мидла

```go
var m map[string]int
fmt.Println(m["x"], len(m)) // 0 0
_, ok := m["x"]             // false
delete(m, "x")              // безопасно
// m["x"] = 1               // panic: assignment to entry in nil map

m = make(map[string]int)
m["x"] = 0
v, ok := m["x"] // v == 0, ok == true
```

`m[k]` возвращает zero value как для отсутствующего ключа, так и для присутствующего ключа с нулевым значением. Поэтому для различения нужен `ok`.

Множество:

```go
type Set[T comparable] map[T]struct{}
s := Set[string]{"go": {}}
_, exists := s["go"]
```

`struct{}` не содержит пользовательских данных и ясно выражает, что важно только наличие ключа. `map[T]bool` иногда удобнее, но позволяет хранить двусмысленное `false`.

## Развёрнутый ответ сеньора: все тонкости

Различие `nil` и пустой ненулевой map важно на границах API. Они имеют одинаковую длину, но `m == nil` различает их; кодировщики могут сериализовать их по-разному, например как `null` и `{}`. Контракт API должен решить, существенно ли это различие.

Ленивую инициализацию удобно использовать только там, где запись происходит под контролем:

```go
if m == nil { m = make(map[K]V) }
```

В конкурентном коде это check-then-act и без синхронизации создаёт гонку. Для разделяемой map инициализация и доступ должны защищаться одним механизмом.

У операции `m[k]++` несколько логических шагов, но синтаксически она разрешена и корректно начинает с zero value. Это не делает её атомарной между goroutine. То же относится к паттерну `if _, ok := m[k]; !ok { m[k] = makeValue() }`: конкурентным вычислениям нужна блокировка, `singleflight` или иной протокол.

При `range` удаление ещё не достигнутых ключей гарантирует, что они не будут выданы; добавленные ключи могут появиться или не появиться. Строить алгоритм на конкретном поведении порядка нельзя.

## Если забыл: что это, зачем и где нужно

`nil` map — «таблица ещё не создана». Читать безопасно, писать нельзя. На собеседовании произнеси: **comma-ok различает отсутствие и zero value, а set — `map[T]struct{}`**.
