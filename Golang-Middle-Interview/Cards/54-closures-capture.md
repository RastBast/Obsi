# Как замыкания захватывают переменные?

## Вопрос

Что захватывает closure в Go, как это влияет на время жизни переменной и какие ошибки возникают в циклах и goroutine?

## Краткий ответ

Замыкание использует переменные из внешней lexical scope, а не снимок их значения по умолчанию. Переменная может escape и жить дольше функции. Для асинхронного вызова нужно понимать, одна ли переменная разделяется между closure или создаётся отдельная на итерацию.

## Развёрнутый ответ мидла

```go
func counter() func() int {
    n := 0
    return func() int { n++; return n }
}
```

Возвращённая функция хранит доступ к `n`. Несколько вызовов одного closure меняют одно состояние. Если closure вызываются параллельно, доступ к `n` требует синхронизации.

Семантика range-переменных зависит от версии языка в `go.mod`; в современном Go итерации получают отдельные переменные, но для старого кода и переменной, объявленной вне цикла, возможен общий capture. Явная передача аргумента остаётся понятной.

## Развёрнутый ответ сеньора: все тонкости

- Capture может заставить переменную escape в heap, но окончательное решение принимает компилятор.
- Closure, сохранённый надолго, удерживает все реально захваченные объекты и способен продлить жизнь большого графа.
- Method value тоже захватывает receiver; value receiver копируется при создании method value, pointer receiver сохраняет указатель.
- Callback под lock опасен: неизвестное замыкание может заблокироваться, вызвать re-entry или изменить порядок locks.

## Если забыл: что это, зачем и где нужно

Closure — функция вместе с доступом к внешнему окружению. Всегда проверь время жизни, конкурентный доступ и то, какую именно переменную она видит.

## Подробное объяснение простыми словами

Замыкание похоже на функцию с рюкзаком: она уносит с собой нужные внешние переменные. Если несколько функций несут одну и ту же вещь, изменение видно всем. Поэтому асинхронный код должен либо делать копию, либо защищать общее состояние.

## Подробное объяснение техническими терминами

Closure формирует environment для free variables. Capture реализуется компилятором и может изменить escape/lifetime. Конкурентная мутация captured variable без happens-before является data race; loop capture нужно оценивать с учётом language version и области объявления переменной.
