# Что такое prefix sum?

Как предварительные суммы позволяют отвечать на запрос суммы диапазона за O(1) и какие расширения применяются для обновлений и двумерных данных?

===

@input

---

## Краткий ответ

Prefix array хранит `pref[i]` как сумму первых `i` элементов, обычно `pref[0]=0`. Тогда сумма полуинтервала `[l,r)` равна `pref[r]-pref[l]`. Построение O(n), каждый immutable range query O(1), память O(n).

---

## Развёрнутый ответ мидла

```go
pref := make([]int64, len(a)+1)
for i, x := range a {
    pref[i+1] = pref[i] + int64(x)
}
sum := pref[r] - pref[l]
```

Дополнительный нулевой элемент убирает отдельный случай `l=0`. Для подсчёта количества значений по условию суммируют 0/1. Prefix XOR аналогично отвечает XOR диапазона.

---

## Развёрнутый ответ сеньора: все тонкости

Обычный prefix плохо поддерживает point updates: последующие значения нужно пересчитать O(n). Fenwick tree даёт update и prefix query O(log n), segment tree поддерживает более общие aggregates/range operations.

Сумма может overflow `int`; выбирают `int64` или проверяемую арифметику. В 2D rectangle sum использует inclusion-exclusion четырёх prefix corners. Для streaming без хранения всех запросов иногда достаточно running sum.

### Дополнительное техническое объяснение

Prefix sum — cumulative homomorphism для invertible aggregate: range result получается через inverse двух prefixes. Для additive group это subtraction. Static preprocessing обменивает O(n) memory/build на constant-time queries.

---

## Если забыл / Простыми словами

Вместо повторного сложения всех покупок между понедельником и пятницей храним общий итог на конец каждого дня. Вычитаем итог до понедельника из итога после пятницы и сразу получаем сумму периода.

### Аналогия и объяснение

Счётчик пробега автомобиля — prefix sum расстояния. Чтобы узнать путь между двумя точками, вычитают два показания одометра. Если прошлые показания постоянно исправляются, нужна другая структура данных.
