# Как выбирать порядок полей составного индекса?

## Вопрос

Что означает правило левого префикса и как equality/range/order влияют на использование `(a,b,c)`?

## Краткий ответ

B-tree упорядочен лексикографически по `(a,b,c)`. Наиболее эффективно запрос фиксирует ведущие columns equality, затем может использовать range следующей. Условие только по `b` обычно не даёт обычный точечный поиск по левому префиксу, хотя planner может применить другие техники.

## Развёрнутый ответ мидла

- Порядок выбирают под реальные WHERE+ORDER BY, а не просто «самое selective первым».
- `(tenant_id, created_at)` подходит списку tenant по времени.
- Индекс может помочь ORDER BY, если направление/order совместимы.
- Два отдельных индекса не всегда эквивалентны одному composite; bitmap combine имеет другую стоимость.

## Развёрнутый ответ сеньора: все тонкости

- Range на раннем column ограничивает эффективность последующих ключей для navigation.
- INCLUDE покрывает SELECT columns без включения их в порядок поиска.
- Skip scan и planner capabilities зависят от версии/статистики; базовый дизайн не полагается на редкую оптимизацию вслепую.
- Redundant indexes увеличивают write amplification; проверяют usage и constraints перед удалением.

## Если забыл: что это, зачем и где нужно

Составной индекс сортирует сначала по первому полю, внутри него по второму и далее.

## Подробное объяснение простыми словами

Телефонная книга отсортирована по фамилии, затем имени. По одному имени искать трудно, потому что одинаковые имена разбросаны среди фамилий. Запросы должны соответствовать порядку каталога.

## Подробное объяснение техническими терминами

Multicolumn B-tree применяет lexicographic key ordering. Equality constraints on leading attributes и inequality on first non-equality attribute определяют contiguous index range; ordering/covering меняют total plan cost.
