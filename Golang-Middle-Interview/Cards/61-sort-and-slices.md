# Как сортировать данные в Go?

## Вопрос

Чем отличаются `sort.Interface`, `sort.Slice`, функции пакета `slices` и стабильная сортировка?

## Краткий ответ

Современный generic-пакет `slices` сортирует ordered values или принимает comparator. Старый `sort.Interface` требует Len/Less/Swap. Обычная сортировка не обязана сохранять порядок равных элементов; стабильная сохраняет.

## Развёрнутый ответ мидла

```go
slices.Sort(xs)
slices.SortFunc(users, func(a, b User) int {
    return cmp.Compare(a.Age, b.Age)
})
```

- Сортировка изменяет slice на месте.
- Для независимого результата сначала делают clone.
- Comparator должен задавать согласованный строгий порядок; противоречивый результат делает поведение бессмысленным.
- Если порядок равных элементов важен, используют stable-вариант.

## Развёрнутый ответ сеньора: все тонкости

- Стабильность обычно дороже по ресурсам; выбирать её «на всякий случай» не нужно.
- Для top-K полная O(n log n) сортировка может быть хуже heap O(n log k) или selection.
- Строковое сравнение — побайтовое, не locale-aware collation.
- Float с NaN требует осознанного порядка; стандартные helpers имеют документированную семантику, custom comparator не должен нарушать транзитивность.

## Если забыл: что это, зачем и где нужно

Сортировка меняет исходный slice. Stable нужна только когда равные элементы должны сохранить прежний порядок.

## Подробное объяснение простыми словами

Обычная сортировка расставляет элементы по правилу, но одинаковые элементы может поменять местами. Стабильная сортировка прикрепляет к одинаковым элементам их прежнюю очередь. Перед сортировкой реши, можно ли менять исходный список.

## Подробное объяснение техническими терминами

Comparator должен формировать strict weak ordering; нарушение antisymmetry/transitivity ломает предпосылки алгоритма. In-place sort использует O(n log n) сравнений в общем случае, а stable variant сохраняет relative order equivalent elements с иной стоимостью.
