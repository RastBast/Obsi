# Чем make отличается от new?

## Вопрос

Что возвращают `new(T)` и `make`, для каких типов применяется `make` и гарантируют ли они heap allocation?

## Краткий ответ

`new(T)` создаёт нулевое значение `T` и возвращает `*T`. `make` инициализирует внутреннюю runtime-структуру slice, map или channel и возвращает само значение, а не указатель на него. Размещение на stack или heap определяет escape analysis.

## Развёрнутый ответ мидла

```go
p := new(int)          // *int, *p == 0
s := make([]int, 3, 8) // []int с len=3, cap=8
m := make(map[string]int)
ch := make(chan int, 1)
```

- `var p *int` даёт nil-указатель, а `new(int)` — ненулевой указатель на нулевой int.
- `var s []int` допускает append, но `make` задаёт длину/ёмкость заранее.
- `var m map[K]V` читается, но запись паникует; `make` подготавливает map к записи.
- `var ch chan T` блокируется навсегда; `make` создаёт рабочий канал.

## Развёрнутый ответ сеньора: все тонкости

- `&T{}` часто эквивалентен `new(T)`, но composite literal позволяет сразу задать поля.
- `make([]T, n)` создаёт n логических zero elements; для последующего append обычно нужен `make([]T, 0, n)`.
- Capacity/hint не является точным обещанием внутренней памяти map.
- Ни `make`, ни `new` сами по себе не определяют heap: компилятор может оставить объект на стеке.

## Если забыл: что это, зачем и где нужно

`new` возвращает указатель на zero value любого типа. `make` запускает внутренний механизм только slice, map и channel.

## Подробное объяснение простыми словами

`new` похож на выдачу пустой коробки и адреса этой коробки. `make` похож на сборку работающего контейнера: списка, таблицы или очереди. Без сборки некоторые нулевые контейнеры нельзя заполнять.

## Подробное объяснение техническими терминами

`new(T)` эквивалентен выделению addressable zero value типа `T` с результатом `*T`. `make` выполняет type-specific initialization дескриптора slice, hash map или channel. Storage class выбирается escape analysis и не является частью семантики built-in функции.
