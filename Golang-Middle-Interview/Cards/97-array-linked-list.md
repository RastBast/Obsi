# Когда массив лучше связного списка?

## Вопрос

Сравните доступ, вставку, удаление и cache locality массива/среза и linked list.

## Краткий ответ

Массив даёт O(1) доступ по индексу и хорошую locality, но вставка в середину требует O(n) сдвига. Связный список при известном узле вставляет/удаляет за O(1), но поиск узла O(n), каждый узел несёт указатели и хуже использует cache.

## Развёрнутый ответ мидла

- Append динамического массива амортизированно O(1), отдельный рост O(n).
- Удаление с сохранением порядка в slice — O(n); без порядка можно заменить последним.
- Linked list не даёт произвольный индекс за O(1).
- В Go `container/list` использует `any` и редко выигрывает у slice для обычных размеров.

## Развёрнутый ответ сеньора: все тонкости

- Заявление O(1) вставки списка предполагает уже найденный node; поиск не исчезает.
- Pointer chasing увеличивает cache misses и GC scan.
- Стабильный адрес node бывает полезен для intrusive structures, но ownership усложняется.
- Deque/ring buffer часто лучше списка для очереди.

## Если забыл: что это, зачем и где нужно

Массив быстрее читает и компактнее; список полезен только при частых локальных перестановках уже известных узлов.

## Подробное объяснение простыми словами

Массив — книги на одной полке: номер сразу ведёт к книге, но вставка в середину сдвигает остальные. Список — каждая книга хранит адрес следующей: вставить легко, но до сотой нужно пройти предыдущие.

## Подробное объяснение техническими терминами

Contiguous storage обеспечивает random access и spatial locality. Linked representation обеспечивает O(1) splice при node reference, но требует O(n) traversal, pointer metadata и увеличивает cache/GC overhead.
