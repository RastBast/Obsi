# Какие ловушки есть у encoding/json?

## Вопрос

Как работают struct tags, `omitempty`, неизвестные поля, числа и различие между отсутствующим, `null` и нулевым значением?

## Краткий ответ

`encoding/json` сопоставляет экспортированные поля и tags. `omitempty` пропускает значения, считающиеся пустыми, но не всегда выражает PATCH-семантику. По умолчанию неизвестные поля игнорируются, а числа в `any` декодируются как `float64`. Для строгого API настраивают Decoder и отдельные DTO.

## Развёрнутый ответ мидла

```go
type Request struct {
    Name  string `json:"name"`
    Limit int    `json:"limit,omitempty"`
}

dec := json.NewDecoder(io.LimitReader(r.Body, maxBody))
dec.DisallowUnknownFields()
var req Request
if err := dec.Decode(&req); err != nil { /* 400 */ }
```

Поля должны быть экспортированы. Tag `json:"-"` исключает поле. `json.RawMessage` откладывает декодирование части документа.

Для больших чисел в динамическом JSON вызывают `dec.UseNumber()`, иначе `float64` может потерять точность целого. Время и custom-типы могут реализовать `json.Marshaler`/`Unmarshaler`.

## Развёрнутый ответ сеньора: все тонкости

Обычное поле не различает «поле отсутствует» и «передан zero value». Указатель различает отсутствие/значение, но `null` и отсутствие часто оба дают nil. Для трёх состояний используют wrapper с флагом присутствия или custom unmarshal. Это критично для PATCH.

После первого `Decode` полезно убедиться, что нет второго JSON value/мусора; один `Decode` не обязательно доказывает полный EOF. Размер body ограничивают до декодирования, а глубину/сложность недоверенного JSON оценивают как security risk.

`omitempty` имеет точные правила пустоты и исторические особенности для struct; поведение новых tag options зависит от версии. Wire contract закрепляют тестами, а domain model не используют автоматически как public DTO: иначе изменение внутренних полей меняет API.

HTML escaping при Marshal по умолчанию защищает некоторые контексты, но может быть нежелателен; Encoder позволяет настройку. Отключение должно учитывать, куда попадёт JSON.

Custom `UnmarshalJSON` должен избегать бесконечной рекурсии через alias type, валидировать инварианты и корректно копировать вход, если сохраняет данные. Map key order в output нельзя использовать как бизнес-контракт, даже если конкретный encoder делает детерминированный выбор.

## Если забыл: что это, зачем и где нужно

Для API помни: **экспортированные поля + tags; strict unknown fields; limit body; `UseNumber`; отдельная модель присутствия/null/zero**. JSON-декодирование — граница валидации, а не просто `Decode`.

## Подробное объяснение простыми словами

Для API помни: **экспортированные поля + tags; strict unknown fields; limit body; `UseNumber`; отдельная модель присутствия/null/zero**. JSON-декодирование — граница валидации, а не просто `Decode`.

Представь запрос как посылку, проходящую через несколько узлов. На каждом участке она может задержаться, потеряться или быть обработана повторно. Поэтому сетевой код обязан ограничивать ожидание, проверять результат и безопасно переживать частичные сбои.
