# Когда применять паттерн functional options?

## Вопрос

Как реализовать функциональные опции для конструктора, какие у паттерна плюсы и где обычная config-структура лучше?

## Краткий ответ

Functional option — функция, изменяющая внутреннюю конфигурацию конструктора. Паттерн удобен для множества необязательных настроек и эволюции API, но может скрывать обязательность, порядок применения и ошибки. Простая config-структура часто яснее.

## Развёрнутый ответ мидла

```go
type Option func(*config) error
func WithTimeout(d time.Duration) Option {
    return func(c *config) error {
        if d <= 0 { return errors.New("bad timeout") }
        c.timeout = d
        return nil
    }
}
```

Конструктор задаёт defaults, последовательно применяет options, проверяет итоговые инварианты и только потом создаёт объект. Обязательные зависимости лучше оставить явными параметрами: `New(client, logger, opts...)`.

## Развёрнутый ответ сеньора: все тонкости

- Нужно определить поведение повторных опций: last wins, ошибка или merge.
- Option не должна запускать неожиданный I/O или сохранять mutable аргумент без копии/контракта.
- `func(*T)` напрямую позволяет сломать инварианты; отдельная закрытая `config` безопаснее.
- Для сериализуемой/сравнимой конфигурации или частых runtime-изменений обычная структура более прозрачна.

## Если забыл: что это, зачем и где нужно

Опции помогают расширять конструктор без длинного списка необязательных параметров. Но обязательное должно оставаться обязательным и видимым.

## Подробное объяснение простыми словами

Сначала создаётся стандартная настройка, затем каждая опция меняет один понятный переключатель. Это похоже на заказ блюда с добавками. Если добавок две, отдельная структура проще; если десятки и они редкие, опции делают вызов читаемее.

## Подробное объяснение техническими терминами

Functional options инкапсулируют mutations конфигурации в closures и поддерживают backward-compatible расширение constructor signature. Корректная реализация валидирует option application order, cross-field invariants, ownership переданных значений и возвращает ошибку до публикации объекта.
