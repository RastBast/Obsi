# Как выбрать случайные k элементов из потока неизвестной длины?

## Вопрос

Как работает reservoir sampling и почему каждый элемент получает одинаковую вероятность попасть в выборку?

## Краткий ответ

Reservoir sampling хранит первые k элементов, а для i-го следующего элемента выбирает случайный индекс `j` в `[0,i]`; если `j<k`, заменяет reservoir[j]. После обработки n элементов каждый имеет вероятность k/n находиться в reservoir. Память O(k), один проход O(n).

## Развёрнутый ответ мидла

Для k=1 сохраняют первый элемент, а i-й (при нумерации с 1) заменяет текущий с вероятностью 1/i. Предыдущий элемент остаётся с вероятностью `(i-1)/i`, что индуктивно даёт равномерность.

Генератор случайных чисел передают зависимостью для тестов. Нужно избегать modulo bias, использовать корректный API равномерного integer range. Алгоритм подходит stream, который нельзя сохранить целиком.

## Развёрнутый ответ сеньора: все тонкости

Weighted reservoir sampling требует другого ключевого/вероятностного алгоритма; простая замена не даёт веса. Для distributed streams локальные reservoirs нельзя бездумно объединить равными долями, если partitions разного размера — нужны counts и корректный merge.

Криптографическая непредсказуемость и статистическая равномерность — разные требования. Для аналитической выборки обычный PRNG часто достаточен, для security — `crypto/rand` и другой threat model.

### Дополнительное техническое объяснение

Algorithm R maintains uniform k-subset invariant. Probability нового элемента быть выбранным равна k/(i+1), а вероятность конкретного старого элемента пережить replacement приводит к k/(i+1). Space не зависит от total stream length.

## Если забыл / Простыми словами

У нас k мест в автобусе, но неизвестно, сколько людей придёт. Каждый новый человек получает честный шанс занять одно из мест, вытеснив случайного пассажира. В конце ранние и поздние участники имеют одинаковые шансы.

### Аналогия и объяснение

Нельзя выбирать только первых k — это смещает выборку к началу. Постепенно уменьшающаяся вероятность замены ровно компенсирует число уже увиденных элементов.
