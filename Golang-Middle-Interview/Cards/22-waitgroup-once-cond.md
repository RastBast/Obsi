# Для чего нужны WaitGroup, Once и Cond?

## Вопрос

Какие задачи решают `sync.WaitGroup`, `sync.Once` и `sync.Cond`, и какие ошибки часто допускают при их использовании?

## Краткий ответ

`WaitGroup` ждёт завершения набора задач, `Once` выполняет функцию ровно один раз, `Cond` позволяет ждать изменения условия под lock. Они не передают ошибки и результаты сами по себе и не должны копироваться после использования.

## Развёрнутый ответ мидла

```go
var wg sync.WaitGroup
for _, job := range jobs {
    job := job
    wg.Add(1) // до запуска goroutine
    go func() {
        defer wg.Done()
        process(job)
    }()
}
wg.Wait()
```

`Add` делают до `go`, иначе `Wait` может увидеть ноль раньше запуска. Счётчик не должен стать отрицательным. Новые циклы использования допустимы только после завершения предыдущего `Wait` по правилам API.

```go
var once sync.Once
once.Do(initResource)
```

Если функция внутри `Do` паникует, `Once` всё равно считает вызов выполненным.

`Cond.Wait` вызывают под lock и всегда в цикле:

```go
c.L.Lock()
for !ready { c.Wait() }
use()
c.L.Unlock()
```

## Развёрнутый ответ сеньора: все тонкости

`WaitGroup` — барьер завершения, а не механизм cancellation или error propagation. Для группы, где первая ошибка должна отменить остальных, удобнее `errgroup.Group` с context или собственная композиция.

WaitGroup можно безопасно использовать одновременно по документированному протоколу, но `Add` для новой независимой партии не должен гоняться с `Wait` предыдущей. Современные версии Go могут предоставлять дополнительные удобные методы; на интервью важно знать базовую семантику версии проекта.

`sync.Once` хорошо публикует результат и создаёт happens-before для последующих `Do`, но ошибка инициализации требует отдельного хранения. Обычный `Once` не повторяет неудачную попытку. Часто проще выполнить fallible initialization явно при старте, чем навсегда кешировать первую ошибку.

`Cond` нужен, когда множество goroutine ждёт сложного предиката над общим состоянием. `Signal` будит одну, `Broadcast` — всех, но разбуженная goroutine обязана повторно проверить условие: до получения lock состояние могло измениться. Канал часто понятнее для одноразового события; Cond полезен для повторяющихся изменений без передачи отдельного значения.

Ни один из этих типов нельзя копировать после использования; обычно их хранят полем структуры и используют pointer receiver.

## Если забыл: что это, зачем и где нужно

Мнемоника: **WaitGroup — дождаться N; Once — выполнить один раз; Cond — ждать предикат**. Ошибки, отмену и результаты проектируй отдельно.
