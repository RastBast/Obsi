# Как устроена map в Go?

## Вопрос

Каковы основные свойства `map` в Go: сложность, порядок обхода, адресуемость элементов и поведение при росте?

## Краткий ответ

`map` — хеш-таблица с ожидаемыми O(1) чтением и записью. Порядок итерации не определён. Элемент map нельзя адресовать, потому что реализация может перемещать его при росте. Обычная map небезопасна для конкурентных записи и чтения.

## Развёрнутый ответ мидла

Ключ должен быть сравнимым типом: числа, строки, указатели, каналы, интерфейсы с сравнимым динамическим значением, массивы и структуры из сравнимых полей. Срез, map и функция ключом быть не могут.

```go
m := make(map[string]int, 100) // hint, а не точная ёмкость
m["a"]++                       // отсутствующее значение читается как zero value
v, ok := m["b"]               // отличаем отсутствие от нулевого значения
delete(m, "a")                 // безопасно даже при отсутствии ключа
```

Порядок `range` намеренно не гарантирован и может различаться между обходами. Если нужен стабильный вывод, ключи собирают в срез и сортируют.

Нельзя написать `&m[key]` или напрямую изменить поле структуры `m[key].Count++`. Значение получают, меняют и кладут обратно либо хранят указатель.

## Развёрнутый ответ сеньора: все тонкости

Конкретное устройство map — деталь runtime и может меняться между релизами, поэтому на собеседовании лучше отделять гарантии спецификации от реализации. Исторически использовались бакеты с несколькими слотами и overflow-бакетами; новые версии runtime могут применять иные схемы. Гарантированы наблюдаемые свойства языка, а не размер бакета или алгоритм эвакуации.

Рост обычно выполняется постепенно, чтобы не создавать большую паузу на полное перемещение. Именно возможное перемещение объясняет неадресуемость значения. Указатель, который хранится как само значение map (`map[K]*V`), стабилен как адрес отдельного объекта, но требует решения вопросов владения и синхронизации.

Хеширование может быть дорогим для больших структурных ключей. Иногда компактный идентификатор или предварительно нормализованная строка лучше, но это подтверждают профилем. `make(map[K]V, n)` — подсказка для уменьшения ростов, не обещание отсутствия аллокаций.

Одновременные чтения без записей допустимы. Любая запись требует синхронизации со всеми конкурентными доступами. Варианты: обычная map под `Mutex/RWMutex`, шардирование, владение одной goroutine или `sync.Map` для подходящего профиля. Сообщение runtime `concurrent map read and map write` — не замена детектору гонок и не гарантия обнаружения каждой гонки.

## Если забыл: что это, зачем и где нужно

`map` нужна для поиска по ключу. Базовая шпаргалка: **хеш-таблица, ожидаемо O(1), порядок не задан, элементы неадресуемы, конкурентная запись небезопасна**. Эти четыре пункта покрывают ядро ответа.
