# Как правильно копировать срезы и не удерживать лишнюю память?

## Вопрос

Какими способами копируют срез в Go? Чем shallow copy отличается от deep copy и как subslice может вызвать утечку памяти?

## Краткий ответ

Независимый верхнеуровневый срез получают через `copy`, `append([]T(nil), src...)` или `slices.Clone`. Но если `T` содержит указатели, map или вложенные срезы, это всё ещё поверхностная копия. Subslice удерживает весь backing array, пока он достижим.

## Развёрнутый ответ мидла

```go
dst := make([]Item, len(src))
copy(dst, src)

clone := append([]Item(nil), src...)
// Go 1.21+:
clone2 := slices.Clone(src)
```

`copy(dst, src)` копирует `min(len(dst), len(src))` элементов и возвращает их количество. После такого копирования изменение самого элемента независимого массива не влияет на исходный, если элемент является обычным значением.

Но для `[][]byte`, `[]map[string]int` или `[]*User` копируются только заголовки вложенных коллекций или указатели. Для полной независимости нужно копировать каждый уровень отдельно.

Типичная проблема:

```go
big := readLargeFile()
token := big[:20]
return token // весь big остаётся достижим
```

Нужно вернуть копию маленького фрагмента: `return bytes.Clone(token)`.

## Развёрнутый ответ сеньора: все тонкости

Термин «утечка» здесь означает не потерянную память, а нежелательное удержание достижимого объекта. GC работает корректно: пока маленький срез содержит указатель внутрь большого массива, массив нельзя освободить. Особенно заметно это в кэшах, очередях и долгоживущих структурах.

При удалении элементов из среза с указательными типами важно обнулить освобождённый хвост, иначе backing array продолжает удерживать объекты:

```go
copy(s[i:], s[i+1:])
var zero T
s[len(s)-1] = zero
s = s[:len(s)-1]
```

Пакет `slices` предоставляет `Delete`, `Clone`, `Compact` и другие операции; поведение по очистке хвоста зависит от функции и версии, поэтому для критичного кода проверяют документацию используемой версии Go.

Нужно различать независимость структуры и объектов предметной области. Универсальной автоматической deep copy в Go нет: семантика владения должна быть явной. Сериализация ради deep copy обычно дорога, теряет типовые особенности и маскирует дизайн-проблемы.

Копирование может быть правильной платой за простое владение и отсутствие гонок. Но на hot path объём копий измеряют benchmark и профилем, а не оптимизируют интуитивно.

## Если забыл: что это, зачем и где нужно

Копия нужна, когда вызывающий код не должен менять ваши данные или когда надо отпустить большой буфер. Формула: **новый backing array не равен deep copy всех вложенных объектов**. Всегда проговори, кто владеет памятью и сколько она живёт.
